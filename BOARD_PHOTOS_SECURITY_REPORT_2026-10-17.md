# Объявления с фотографиями и проверка безопасности

Дата: 17 октября 2026 года. Выпуск: `2026-10-17-board-photos-security-r1`.
Основа: актуальный `main` после `c33c22d` с редактируемым водяным знаком галереи.

## Фотографии объявлений

- На одно объявление можно добавить до **5 фото** при создании или позже в редакторе. Отдельные снимки можно удалить или заменить. Текст редактируется вместе с фото.
- В списке показывается первое фото, на странице объявления — все. Изображения помещаются в экран целиком; место под них резервируется до загрузки.
- Для страницы создаётся уменьшенный JPEG. Нажатие открывает оригинал; исходные байты сохраняются. Изменение размера предпросмотра обновляет его кэш.
- Редактировать могут автор и модераторы 101/102/103/105. Старые объявления без фотографий продолжают работать без массовой миграции.
- Удаление объявления, рубрики или очистка просроченных объявлений удаляет соответствующие файлы. Просроченное объявление сразу перестаёт выдавать оригиналы и предпросмотры по прямым ссылкам.

Настройки находятся в **Админка → Настройки фотографий объявлений**, также доступны из управления объявлениями.

| Настройка | Диапазон | По умолчанию |
|---|---|---|
| Фото на объявление | 0–5 | 5 |
| Размер одного файла | 1–32 МБ, в пределах серверного лимита | 8 МБ |
| Максимальная сторона оригинала | 320–12000 px | 8000 px |
| Размер предпросмотра | 240–1200 px | 640 px |
| Форматы | JPG, JPEG, PNG, GIF, WebP | Все перечисленные |

Ноль отключает новые загрузки. Уменьшение лимита не удаляет существующие фото. Дополнительно действуют лимит всей отправки 64 МБ, максимум 40 Мп и проверка доступной памяти. Очень большое фото может быть отклонено по памяти раньше предела в пикселях.

Настройки хранятся отдельно в `local/board-settings.json`, фотографии — в закрытом `local/attachments/board`. Настройки и вложения входят в резервное копирование. Поставка не заменяет `/data/local` или пользовательские оригиналы.

## Найдено и исправлено

| Участок | Проблема | Исправление |
|---|---|---|
| Объявления | Удаление по смещающимся номерам строк; устаревшие формы могли затронуть другую запись | Стабильные ID, версии списков и записей, блокировка записи, атомарное сохранение |
| Редактирование фото | Изменение только снимков не отражалось бы в версии текстовой строки | Версия редактора включает список файлов; конфликт возвращает HTTP 409 |
| Загрузка изображений | Проверка заголовка картинки не доказывала, что её можно декодировать | Проверка реального содержимого через GD, размера, MIME, пикселей и памяти; недопустимая загрузка не сохраняет объявление |
| Старые формы и игровые действия | Не везде были CSRF-проверки; некоторые действия выполнялись переходом по ссылке | Общая проверка POST, токенов, Origin/Fetch Metadata; автоматическое добавление токенов в старые формы; защищённые POST-кнопки для выявленных действий |
| Вход и выход | При входе не обновлялся ID сессии; старые cookies не имели всех защитных флагов; пароль принимался в URL | Новый ID сессии и токен после входа, Secure/HttpOnly/SameSite=Lax; вход через POST, выход через POST; убрана подсказка хранить пароль в закладке |
| Восстановление пароля | Ключ выводился из времени и не проверял срок действия | Случайный 256-битный ключ, в профиле только SHA-256 и срок; 12 часов; подтверждение POST; пользователь сам задаёт новый пароль; одноразовое использование. При отключённой почте запрос ссылки не меняет данные профиля. Старые ссылки нужно запросить заново |
| «Пирамида» | Закодированное имя ответа могло закрыть textarea и внедрить HTML/скрипт | Экранирование после декодирования; удаление и настройки защищены CSRF |
| «Пирамида» | Автоочистка обращалась к другому файлу сообщений | Очистка правильного файла с соблюдением заданного предела |
| Резервные копии | Восстановление ZIP не ограничивало явно все пути и ссылки | Предварительная проверка всех записей, запрет выхода из `local`, скрытых путей и символьных ссылок; существующие файлы не заменяются; POST+CSRF |
| Админская информация о движке | Старый внешний HTTP-сервис мог отдавать HTML прямо в админку; при отключённых URL-потоках возникали предупреждения | Удалена автоматическая подгрузка внешнего HTML; показана информация о текущем способе обновления |
| PHP 8 и временный кэш | `count()` от строки, отсутствующие файлы кэша, неопределённые значения рейтингов/контактов/лотереи/настроек | Исправлены причины предупреждений и ошибки просмотра исходника; кэш безопасно пересоздаётся |
| Старые переключатели WAP/WWW | Ссылались на удалённые темы и необъявленную переменную | Выбирают существующие мобильную и широкую темы |
| HTTP-защита | Не было запрета встраивания в чужую страницу | Добавлены X-Frame-Options и CSP для frame-ancestors/base-uri/object-src |

Восстановление ZIP ограничено 50 000 записями, 64 МБ на файл и 1 ГБ распакованного содержимого. Проверка путей выполняется до записи первого файла. Старые служебные `.htaccess` и файлы блокировок внутри архивов пропускаются: правила доступа задаёт сервер, а не архив. Эта операция восстанавливает отсутствующие файлы, а не откатывает существующие.

## Проверка

Проверка выполнялась на изолированных копиях с временными аккаунтами. На опубликованном сайте — только чтение. Проверяются весь состав собранного приложения и синтаксис PHP/MOT/JS; вручную рассмотрены вход, сессии, восстановление, загрузки/выдача файлов, архивы, формы, роли, текстовый вывод и операции записи. Пользовательские данные и исходные архивы не подменялись.

Итоговые `npm test` и `npm run test:browser` завершены успешно.

## Оставшиеся ограничения

**Прежнее хранение паролей остаётся отдельным известным риском:** двойной MD5, обратимое содержимое cookies «Запомнить меня» и исходный пароль в серверной сессии. Владелец ранее отдельно просил сохранить механизм паролей; этот запрет зафиксирован в `AGENTS.md`. В этом выпуске защищены сессии, транспорт формы и восстановление, но формат хранения паролей массово не менялся. Поэтому утверждение «все уязвимости сайта устранены» было бы неверным.

Отправка почты в существующей конфигурации Railway отключена (`sendmail_path=/bin/false`). Проверены выдача/срок/одноразовость ключа и обработчик восстановления, доставка письма не подтверждена. Это относится и к прежней версии сайта.

Проверка не является доказательством отсутствия любых ошибок во всех сочетаниях старых модулей. Не проводились нагрузочная атака на рабочий сайт, аудит инфраструктуры провайдера и испытания на физических телефонах. Настройки сервера и клиентские ограничения не заменяют последующего обновления старого механизма паролей.
