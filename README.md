# WAP-MOTOR 21: тестовая копия

Основа — последняя подтверждённая владельцем сборка wapmotor_php84_footer_clean.zip, объединённая с проверенными исправлениями PHP 8.4 и запуска Railway. Сохранены название «Лесика», очистка демонстрационной рекламы и удаление согласованной строки внизу страниц. Выпуск: 2026-10-15-smile-picker-r1. Сборка состоит из прежнего базового motor-source.tar.gz и актуального кода motor-code.tar.gz. Второй архив не содержит каталога local: существующие настройки и данные не публикуются. Docker распаковывает базу, затем накладывает актуальный код. Для последней версии используйте текущий main и Dockerfile, а не один базовый архив. Изменения движка перечислены в CHANGES.json. Авторские уведомления и условия сохранены в исходниках (help/LICENSE.html).

## Тестовый адрес и первоначальная настройка

https://motor-testing.up.railway.app

Сайт закрыт отдельным HTTP-паролем. Данные доступа передаются владельцу отдельно и отсутствуют в репозитории. После входа откроется установщик: владелец знакомится с соглашением, создаёт администратора и задаёт HTTPS-адрес сайта. После установки удалите INSTALL.php из админки. При следующем запуске контейнера установщик также удалится автоматически, если профиль администратора уже существует.

## Развёртывание

Railway: проект motor21-test, сервис motor, окружение testing. Источник — main этого репозитория. Используется Dockerfile; настройки healthcheck /_health, таймаута 120 секунд и перезапуска ON_FAILURE заданы в Railway. Устаревший railway.json удалён: Config as Code больше не принимается Railway.

Данные и сессии хранятся на постоянном диске /data. Только одна реплика сервиса. Переменные MOTOR_TEST_USER, MOTOR_TEST_PASSWORD и PORT настроены в Railway. Apache использует только mpm_prefork; конфигурация проверяется apache2ctl -t при сборке и перед запуском. Скрипт инициализации вызывается через CMD, чтобы выполняться на Railway.

Изменения кода через редактор админки не переживают новое развёртывание; обновляйте код в репозитории. Не распаковывайте motor-source.tar.gz вручную в корень репозитория.

## Проверки и ограничения

PHP 8.4: проверен синтаксис 178 PHP-файлов. В изолированной копии выполнены 147 запросов: реальные multipart-загрузки, все 16 расширений, лимиты, редактирование, удаление, права, диапазоны байтов видео, резервное копирование и восстановление. Также пройдены проверки семи тем и прежних разделов. Тестовые пользователи и данные не включены в исходный архив. Сборка Docker повторно проверяет синтаксис на нативном PHP и наличие расширений.

Готовность реального контейнера контролируется HTTP-проверкой /_health. Главная и установщик требуют HTTP-пароль; каталоги local и includes закрыты для прямого доступа. Загрузка проверена в изолированном PHP 8.4; действующая учётная запись администратора владельца для тестов не использовалась. Проверка воспроизведения на физических Android/iPhone не выполнена.

Почтовая отправка и чтение внешних URL отключены в тестовой конфигурации. Схема паролей пользователей остаётся старой: используйте отдельные тестовые пароли. Данные отдельного сайта «Лесика» не переносились; его семь палитр уже перенесены в оформление Motor.

## Обновление существующих данных

migrate.php выполняет миграцию 2026-10-15-footer-clean-v1 один раз. Меняются только старые стандартные значения названия, приветствия, внешнего адреса и логотипа, а также точно совпадающие исходные рекламные файлы. Логин, пароль, адрес сайта и другие изменённые владельцем настройки сохраняются. Перед изменением исходные файлы копируются в /data/motor-backups/2026-10-15-footer-clean-v1. Каталог недоступен через сайт. Метка выполненной миграции находится в /data/.motor-migrations.

Правило выбора исходной версии зафиксировано в AGENTS.md: уточнять сборку у владельца и по умолчанию выбирать последнюю версию с изменениями.

## Фото, видео и файлы

Вложения доступны при создании и редактировании новостей, тем и ответов форума. Автор может редактировать своё сообщение в открытой теме, модератор — через существующее управление форумом. Новости публикуют администраторы согласно прежним правам движка.

Настройки: **Админ-панель → Фото, видео и файлы — настройки вложений** (`/mpanel/attachments.php`). Для форума и новостей отдельно: общее количество на запись (0–10), размер одного фото/видео/файла (1–32 МБ), разрешённые расширения, максимальная сторона фото и ширина показа. Исходно: 5 вложений, фото 8 МБ, видео 24 МБ, документы 8 МБ, сторона фото до 8000 px и 40 Мп. Общая отправка ограничена сервером 64 МБ. Уменьшение лимитов не удаляет ранее загруженное.

Фото: JPG/JPEG, PNG, GIF, WebP. Видео: MP4, WebM. Файлы: PDF, TXT, CSV, ZIP, DOCX, XLSX, PPTX, ODT, ODS. Для телефонов рекомендуется MP4 с H.264/AAC. Сервер не перекодирует видео; воспроизведение зависит от кодека браузера. Для каждого вложения есть скачивание.

Файлы хранятся в `local/attachments`, выдаются только через `attachment.php` после проверки существования записи и общих ограничений доступа движка. Прямой доступ к `/local` закрыт Apache. Удаление новости, сообщения, темы или раздела и автоочистка старых тем удаляют вложения. Новые сообщения форума имеют дополнительное поле UUID; старые записи получают его при редактировании. Старые поля и данные сохраняются. Миграция существующих записей при запуске не нужна.

Резервная копия включает каталог attachments и attachment-settings.json при выборе соответствующих каталогов и главных файлов. Исправлены ошибки старого PclZip на пустых файлах и числовом лимите памяти PHP 8.4.

## Повторение проверок разработчиком

В рабочей копии текущего main выполните `npm install`, затем `npm test`. Скрипт соберёт из двух архивов изолированную папку .test-site, затем выполнит проверки. Зависимости проверок зафиксированы в package.json. Тесты используют только виртуальную файловую систему PHP WebAssembly и временные учётные записи, не обращаются к опубликованному сайту. Результат проверки вложений — `checks/results.json`. `validate.php` дополнительно запускается при сборке Docker.

## Смайлы и эмодзи

Выпуск 2026-10-15-smiles-r1 продолжает последнюю сборку с вложениями. Обычные коды (`:)`, `:hello`) и эмодзи (`😊`, `👍🏽`, семейные эмодзи) проверены в новостях/комментариях/RSS/главной ленте, форуме, гостевой и ответах администрации, мини-чате, чате администрации, галерее/подписях/комментариях, объявлениях, поле «О себе», личной переписке, голосованиях/архиве и сообщениях пирамиды. Отдельных модулей блогов и городской газеты в текущем движке нет.

Исправлено модераторское редактирование форумных смайлов. Лимит учитывает сами смайлы, а не двоеточия во времени и ссылках; ссылки и блоки кода не изменяются. Административные смайлы доступны для вставки администрации, их сохранённые изображения видны читателям. Общий лимит смайлов из существующих настроек сохраняется. Изображения смайлов ограничены 96 × 48 px с сохранением пропорций; вид эмодзи зависит от шрифтов устройства.

`checks/smiles.mjs`: 89 запросов, 25 представлений, 121 проверенный GIF, 10 групп проверок, семь тем; результаты в `checks/smiles-results.json`. Все данные и учётные записи тестов существуют только в изолированной памяти. Изменения не требуют миграции пользовательских записей. Физические телефоны не проверялись. Повторно прошли 147 запросов проверки вложений и проверки тем.

## Компактный выбор смайлов

Выпуск 2026-10-15-smile-picker-r1: кнопка «☺ Смайлы» под полем сообщения. Панель закрыта по умолчанию, находится в потоке страницы и не перекрывает экран. Высота ограничена 232 px и адаптируется к видимой области; внутри прокручиваемая сетка. Кнопки смайлов — не менее 44 × 44 px. После выбора код или эмодзи вставляется в позицию курсора (или заменяет выделение), панель закрывается. Есть поиск, Escape, кнопка закрытия, закрытие по нажатию снаружи и защита длины поля.

Подключены новости и редактор новостей; темы, ответы и редактирование форума; гостевая, ответы администрации и редактирование; мини-чат; чат администрации; подписи и комментарии галереи; объявления; личная переписка, быстрая почта администрации и объяснение бана; «О себе»; вопросы и ответы опросов; сообщения пирамиды. Всего 48 объявлений полей в 21 файле, проверены 28 вариантов страниц. Редактор исходного кода и служебные поля не получают панель.

В каталоге 105 общих смайлов, 16 административных (с прежними правами) и 32 эмодзи. Для полей с поддержкой только обычных кодов административный набор не предлагается. На странице списка смайлов нажатие копирует код; при недоступном буфере обмена показывается подсказка. Лимит смайлов в сообщении по-прежнему задаётся существующей настройкой движка.

Проверено в Chromium 153: 35 раскладок (ширина 320–740 px, семь тем), настоящие события касания, положение курсора, несколько полей, поиск, ограничения длины и отсутствие неожиданных отправок формы. 150 запросов функциональных/защитных проверок, 147 запросов регрессии вложений, синтаксис 178 PHP-файлов и JS. На физических телефонах не проверялось.

Безопасность и обнаруженные ограничения старого ядра описаны в SECURITY_REVIEW.md. Настройки и записи пользователей не менялись. Старые короткие токены формы автоматически обновятся: если форма была открыта до обновления, её потребуется обновить перед отправкой.

`npm test` включает проверки панели и защиты (checks/picker-backend.mjs) и создаёт временные HTML-файлы в checks/fixtures. Для отдельной браузерной проверки в Linux: `npm install --no-save playwright@1.62.1 @sparticuz/chromium@153.0.0`, затем `npm run test:browser`. Браузер запускается только на локальных тестовых HTML; реальный сайт не используется для отправок. При необходимости путь к установленному Chromium можно передать через MOTOR_BROWSER_EXECUTABLE. Сборка production не использует Node-зависимости.
